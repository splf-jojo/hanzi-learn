# Roadmap: chinese_app + chinese_ocr → один продукт

Цель: **один** доведённый, задеплоенный и измеримый репозиторий вместо двух начатых.
Правило на всех этапах: мелкие коммиты по ходу работы (не дампом), тесты на сервисный слой, CI зелёный.

---

## v1 — Слияние и гигиена

**Цель:** один репозиторий, который поднимается одной командой.

- За основу бэкенда взять архитектуру `chinese_ocr` (api / services / repositories), в неё перенести домен `chinese_app` (words, sentences, groups, notes, progress).
- Закоммитить незакоммиченный рефакторинг `chinese_ocr` **до** начала слияния.
- Alembic вместо самописных `ALTER TABLE` на старте; Pydantic-схемы вместо `payload: dict`.
- `docker-compose` (postgres+pgvector, backend, frontend), CI (сборка + тесты), убрать `logs.txt` из репо, ротировать OpenAI-ключ.
- Тесты: сервисный слой обоих доменов, моки на OCR/CLIP/LLM.

что убираем у chinese_ocr:
- создание и сохранения и вся другая логика  ии карточки

на фронте:
- будет новая вкладка в сайдбаре photo, там будет как у chinese_ocr галлерея и загрузка фото 
- стрница фото также делает боксы при нажатии сайдбар с словом и все без карточки пока чисто слово

код ВАЖНО:
- код обязан быть scalable 
- код должен быть читаемым и атомарным

**Готово когда:** `docker compose up` на чистой машине поднимает оба домена; CI зелёный; история из осмысленных коммитов.

## v2 — Техники изучения, FSRS, деплой, первая метрика

**Цель:** продукт, которым вы сами пользуетесь ежедневно, и первое число в README.

- FSRS через `py-fsrs` поверх существующих `last_seen_at` / `next_review_at` (сейчас колонки не пишутся).
- Нормальные режимы: recall/recognition, ввод, разбор по иероглифам; чистка фронта, добить `Radicals` / `Progress` или убрать из навигации.
- Полная интеграция OCR-части: фото → кропы → карточки падают в общую очередь повторений.
- Публичный деплой (VPS / Fly.io) + английский README с GIF-демо.
- **Eval-датасет:** ~50–100 своих фото с ручной разметкой → точность PaddleOCR как бейзлайн. Это фундамент для v4.

**Готово когда:** живой URL; FSRS планирует реальные повторения; в README есть число точности OCR на своём датасете.

## v3 — Object recognition на готовой модели

**Цель:** фото → объекты → карточки, без обучения своих моделей.

- Готовая open-vocabulary модель (напр. OWL-ViT / GroundingDINO) за флагом конфига.
- Кропы объектов → существующий CLIP+pgvector поиск → LLM-карточка (переиспользовать `learning_cards` с кэшем).
- Метрика: доля фото, где предложенные объекты релевантны (ручная разметка на том же датасете).

**Готово когда:** режим «сфоткал комнату → получил набор карточек» работает в проде за флагом.

---

## v4 — Своя OCR-модель (recognition-only)

**Цель:** превратить проект из MLE-glue в ML-пункт резюме.

**Жёсткий скоуп — без него не начинать:**
- Только **распознавание кропов**, детекция остаётся за PaddleOCR.
- Словарь ограничен (топ-3000 иероглифов HSK).
- Данные: синтетика (рендер шрифтов + аугментации); фото из v2 — только как тест.
- Одна архитектура (CRNN или SVTR), без зоопарка.
- Цель — **честное сравнение с бейзлайном + анализ ошибок**, а не «побить Paddle». Проигрыш с внятным разбором — тоже результат.
- Модель встаёт в прод за флагом `OCR_ENGINE=custom|paddle`.

**Готово когда:** в README таблица «своя модель vs PaddleOCR» на датасете из v2 + раздел с разбором, где и почему модель проигрывает.

**Геометрия пространственных конструкций («бутылка НА столе»)** — исследовательская задача, плохо совместимая с вечерним режимом, и точка вероятного бросания. Опционально — только если v4 закрыт.

## Критерии «проект усиливает профиль»

1. Живая git-история.
2. Тесты + CI.
3. Публичный работающий URL.
4. Хотя бы одно измеренное число.
5. Английский README с диаграммой и демо.
